# 架构总览

## 顶层设计

三层，不要混：

1. **产品语义**（与语言无关）— 工作区、流水线、库表意图  
2. **实现** — `mac/` 主线，`win/` 随后  
3. **文档** — `docs/` 只服务文档站网页  

```text
        文档 docs/
            │ 约束
      ┌─────┴─────┐
      ▼           ▼
     mac/        win/
    当前产品     下一阶段
```

## 仓库目录（入库）

```text
LitNexus/
├── docs/          # 仅网页文档源
├── mac/           # Mac 原生
├── win/           # Windows 原生：Core / WPF 基础工程与 selftest
├── mkdocs.yml
└── README.md
```

本地可能还有不入库的目录（如旧 `python/`、本机 `AGENTS.md`），不参与产品结构。

## 产品分层（概念）

```text
UI（mac / 未来 win）
  → 流水线
    → EPMC · 数据库 · AI · CSV
      → 工作区磁盘契约
```

各端各自实现；磁盘契约与流水线语义一致。详见 [多端策略](platforms.md)。

## 桌面界面层级

四个主体页面的主要内容卡片使用统一的形状与 14 pt 圆角，卡片内部可独立成组的内容容器统一使用 10 pt 圆角。输入框、按钮、标签和其他控件使用更小的圆角，以区分内容层级；不得为单个主体页面另设卡片圆角。页面标题与图标在内容列内保留至少 6 pt 的绘制安全边距，卡片继续使用内容列基准线，不得用贴边裁剪截断字形或图标描边。

编辑器的行号栏使用独立的中性底色和分隔线，不复用外层卡片底色。跳转到网页指南的整行入口使用弱强调色底色与强调色边界，必须与普通信息卡和输入框明显区分。

导航项的选中状态不得改变文字或图标的字体度量；通过颜色、底色和边界表达选中，避免切换页面时发生文字位移。

应用使用固定、不随路由变化的最小内容尺寸基线，必须足以容纳侧栏、运行页的主操作栏和首次设置当前步骤的完整宽度。高度不足时，首次设置与主体内容必须能够滚动；不得裁切主要卡片、隐藏主要操作，或让工具栏因自然压缩形成临时竖排。若未来支持更窄窗口，必须在明确断点下设计紧凑布局。

首次设置的步骤切换使用带方向的短距离淡入过渡，主体卡片尺寸与阴影保持不动；配置页标签按横向顺序交叉淡入，并让选中背景平滑移动。四个主体页面按左侧导航的纵向顺序使用两阶段淡出／淡入：旧页短暂淡出，完全透明时替换内容，新页再从相应方向淡入；任何时刻只挂载一个主体页面，不得叠放两张复杂页面形成文字、卡片或图表重影，也不得使用整页大幅滑动。常规动态效果下，旧页退出不超过 100 ms，新页进入不超过 140 ms，从选择到稳定完成不超过 250 ms，两个阶段之间不得故意停留为空白；这是体验预算，各端可使用等效的动画曲线。所有位移应遵循系统“减少动态效果”设置。页面与标签切换的动画事务只作用于固定的内容承载区；窗口标题栏、工具栏、左侧导航及其尺寸和布局不得继承该事务。导航选中提示如需动画，只可局部改变其背景，不得触发布局动画。四个主体页面共享一个稳定的顶层滚动宿主，页面切换只替换其内部内容。在 macOS 上必须在窗口生命周期内显式固定 `NSWindow.titlebarSeparatorStyle`，页面切换不得重新计算或闪动窗口 chrome。
